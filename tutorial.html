01

新手教程：先把模型和上下文调对

安装完成后，只需要三件事就能开始干活：配好模型、选对推理强度、给够上下文。

模型配置

入口：设置 → 模型。Desktop Agent 把模型当成可插拔配置，不是硬编码依赖 —— 云端 API、OpenRouter、本机 Ollama / llama.cpp 都能接，随时换。

槽位负责什么建议怎么选
主脑 primary 推理、工具调用、长上下文任务 选能力最强、支持工具调用的模型；本地跑至少 8B 以上量化模型
视觉 utility_mm 图片 / 音频 / 视频侧看（截图、录屏、语音） 需要看图就配 qwen-vl / omni 类模型；纯文本任务可不配
兜底 fallback 主链失败时接管 retry + fallback 配一个稳定便宜的第二家，避免单点故障

接本地模型（零 API Key）

  1. 启动本地推理服务Ollama 默认监听 127.0.0.1:11434；llama.cpp 用 llama-server 起 HTTP 服务并记下端口。
  2. 在设置里新增模型类型选 ollama / llama_cpp / openai_compat，填 base_url 与模型名。识别到本地服务时会跳过凭证校验直接探活注册。
  3. 点测试连通性返回正常再设为主脑。填了占位 Key（如 123）时，测试可能过但实际调用会报 401 —— 本地服务请留空 Key。
NOTE

也可以直接让 AI 自己配：说一句「帮我把本地 llama.cpp 的 Qwen 加进来并测试连通」， 主脑会走 model_catalog 技能完成注册与验证，不用手点面板。

推理强度

推理强度（reasoning 档位）决定模型在回答前「想多久」。档位越高，方案越周全、 工具调用越稳，但耗时和 token 也越多。在模型配置项里按模型单独设置。

档位适用场景代价
关闭 / off闲聊、简单问答、纯检索、批量改名最快最省，复杂任务容易想漏
低 low日常办公：写文档、查数据、单文件改动响应快，够用
中 medium多步任务、脚本编写、网页抓取、报告生成推荐日常默认档
高 high架构设计、疑难 bug 定位、跨仓重构、方案评审慢且贵，值得用在关键决策上
本地模型

llama.cpp 的 --reasoning-format 默认是 none（等于关掉推理）。 想用三档推理，必须在启动脚本里显式设置该参数，档位再通过请求级 budget 传递。 验证档位时建议另开一个端口起探针实例，别动正在用的主服务。

上下文设置

上下文长度决定 AI 一次能「记住」多少内容 —— 对话历史、读到的文件、工具返回都算在里面。 设置项在模型配置里，关键是把 声明值 和 真实值 对齐。

上下文长度怎么填

填模型服务真实可用的窗口大小，不要照着宣传值虚高填。

  • 本地 llama.cpp：以启动参数 -c / --ctx-size 为准
  • 多人共用服务要除以并发数，否则会被别人挤爆
  • 填大了 → 到不了压缩阈值就被服务端截断，表现为「答非所问」
压缩阈值

用量达到设定比例（默认约 90%）时触发自动压缩，把早期对话摘要化腾出空间。

  • 一发消息就压缩 = 声明的上下文太小，或阈值设太低
  • 长任务建议调高上下文而不是频繁压缩
  • 压缩是有损的，关键约束请写进文件或规则里

四级压缩机制（了解即可，自动生效）

  • L0 会话分页：超长工具回包分页，按需翻页读回
  • L1 任务 pin：当前任务的关键信息钉住，不被压掉
  • L2 回包 compact：工具结果就地精简，只留结论与路径
  • L3 offload 落盘：大输出写进 output/files/，需要时再读文件，而不是塞满窗口

第一次对话：怎么说才好用

把 Desktop Agent 当成一位能动手的自动化工程师，而不只是聊天机器人。

这样说
  • 「读一下 output/ 里的 sales.xlsx，按区域汇总，出一份 HTML 报告」
  • 「打开这个网页，把表格抓下来存成 CSV」
  • 「每周一早上 9 点把这个报表发我微信」
避免这样
  • 「帮我处理下数据」—— 没说哪份数据、要什么结果
  • 一句话塞十个需求 —— 拆成几步，或让它先出清单
  • 要求它编造没查到的事实 —— 它会如实说缺口，这是设计如此
TIP

需要它改文件、跑脚本时，注意输入框旁的能力徽章：工作模式可写文件 / 跑 Shell / 派子代理， 询问模式只读。点徽章即可切换。

02

功能介绍：九个模块各管什么

左侧活动栏 / 设置里能看到的九大功能区，按「做什么事找哪个」来记。

文件

所有产物的统一归口。AI 干活时读写的文件都落在会话工作区里，交付物按类型分目录， 聊天底部的文件卡片可以直接打开抽屉查看。

目录放什么
output/files/文档、HTML、PDF、Excel、日志
output/images/ · videos/ · audio/图片、视频、音频产物（聊天里可直接预览）
output/tables/表格数据，大表优先存 parquet
output/scripts/固化后的 RPA 脚本
input/你拖进来的附件
inbox/已登记的交付物（文件抽屉就是看这里）

文件面板支持代码高亮预览、Office 文档预览（docx / xlsx / pptx）与 HTML 编辑。 想授权 AI 改工作区以外的目录，说一句「我要整理桌面上的 xx 文件夹」，它会请求路径授权后再动手。

报告

两种交付形态，按场景选：

Canvas 看板

聊天内的结构化卡片 / 报告页，适合结论 + 证据 + 下一步。

  • 表格、图表、指标行、对比矩阵都能画
  • 不落地成文件，随会话保存
  • 长文分析优先用它，聊天里只留一两句导读
HTML / 文档报告

要发给别人、要留档，就出文件。

  • 精美业务 HTML 报告（内置模板库）
  • Word / Excel / PPT 直接生成
  • 动画 HTML 幻灯片，可用于汇报
  • PDF 读写：提取、合并、加水印、填表单

示例说法：「把这份调研整理成一页 HTML 报告，发我文件」或「用 Canvas 给我做个数据看板」。

脚本库

把一次性操作固化成可重复运行的 RPA 脚本。会话里探索阶段写的临时脚本在工作区 scripts/；确认好用后固化进脚本库（output/scripts/），之后可以一键运行或挂定时。

  1. 探索先用自然语言让它做一次，比如「把这个文件夹里的图片批量压缩」。
  2. 固化说「把这个存成脚本任务」，它会把工作区脚本登记为 RPA 任务。
  3. 运行脚本库面板里点运行，或让 AI 调 run_script。
  4. 定时说「每天早上 8 点跑一次」，它会用 5 段 cron 注册定时计划。
支持类型

python · playwright（浏览器自动化）· shell 等。定时任务的结果可以通过微信 / 站内通知推给你。

插件

插件是给 Desktop Agent 加专属界面和专属能力的扩展包，装在 extensions/user/ 下。适合把一套高频业务操作做成带按钮的面板，而不是每次打字。

能做什么
  • 自定义页面 / 表格 / 流程图面板
  • 对接你自己的 HTTP 接口、上传入口
  • 在右侧抽屉里常驻，随时调用
怎么造
  • 说「我要做一个 xx 插件」→ 走脚手架模板
  • 复杂插件可交给 Coding CLI 实现
  • 自带校验、探活、浏览器实测

专家组

专家是带特定人格与专长的角色（如架构评审、代码审查、文案策划）。 在对话里 @专家名 即可临时套用该视角；需要多位专家协作或长时间独立作业时，才升级为子代理派发。

  • 单个专家：直接套用角色回答，不起新进程，最轻量
  • 多位专家：可并行派发，各自带独立上下文与验收标准
  • 适合场景：方案评审、代码 review、多角色内容共创

子代理

主脑把可并行或耗时长的子目标派给独立子代理执行。子代理自带工作区，跑完把结论交回主脑汇总 —— 主脑的上下文不会被中间过程塞满。

什么时候用为什么
多个互不依赖的子任务并行跑，总时长≈最慢那个
长时间 agentic 作业避免主会话上下文被过程日志吃掉
需要独立验收的改码任务带 QA 流程派发，交付前跑测试

用法：说「这几件事并行处理」或「派子代理去做」。主脑会画一张带并联边的任务图， 然后按批派发；进度在任务清单里可见。

技能管理

技能是按需加载的能力包：浏览器自动化、PDF、Office、飞书、抓站、出图、终端…… 平时只加载索引（省上下文），真正要用时才展开细则和工具。

层级含义开销
L0常驻系统工具，随时可用零
L1技能 / 工作流 / 专家索引极低
L2技能入口说明低
L3参考文档 + 具体工具组解锁按需
  • 技能市场：可从开源生态搜索并安装新技能
  • 自建技能：说「把这套流程做成技能」→ 走技能创建向导，产物在用户技能目录
  • Playbook：每个技能可沉淀「做这件事的正确姿势」，成功后自动写回，下次少走弯路

工作流

工作流 = 可执行、可复用、可定时的编排。两层概念别混：

过程清单（草稿）

会话内的执行 checklist，随任务自动创建、逐步打勾。

  • 看得到当前进行到哪一步
  • 标完成必须附证据（产物路径 / 命令）
  • 用完即弃，不进库
工作流库（Library）

确认过的流程存成模板，可反复运行。

  • 支持串行 + 并联的 fork-join 图
  • 可绑定时器（cron 或单次）
  • 最后一步可挂推送渠道：站内 / 微信

示例：「把刚才这套流程存成工作流，每周一 9 点跑，结果发我微信」。

知识库

知识库是 AI 的长期记忆总结，给主脑自己用 —— 不是给你上传文档做检索的网盘。 它把跨会话的经验沉淀成结构化条目，新会话开场就作为背景注入。

知识域存什么什么时候被用
sessions历史会话摘要（做过什么、结论是什么）你提到「上次那个」「之前我们」时检索
lessons踩过的坑与修复方式新任务前自动参考，避免重复犯错
personality你的偏好与习惯决定语气、默认选择、交付形式
playbook某类任务的标准做法遇到同类任务直接照做
注意

想让它记住某件事，直接说「记住：以后报表都用这种格式」即可，会写进长期记忆； 想让它忘掉或修正，说「之前那条记错了，改成……」。

03

记忆提取机制与历史归档

会话结束不等于失忆。三层结构：当场记得住、事后找得回、长期用得上。

记忆提取机制

记忆不是一整坨塞进上下文，而是分层按需提取：

  1. 常驻摘要（自动注入）开场就带上：你常做的事、在做的项目、已沉淀的教训、近期会话时间线。这部分很轻，保证「新会话也认得你」。
  2. 相关性召回（自动触发）你的话里出现「上次」「之前」「那个项目」时，系统按语义 + 关键词把最相关的历史片段捞出来，只捞需要的几条。
  3. 主动检索（按需调用）需要更多细节时，AI 会去检索归档记忆或读原始会话摘要，而不是靠「印象」编造。
  4. 上下文压缩（超长时）会话过长触发压缩，早期内容摘要化；关键约束钉住不丢，大输出落盘按需回读。
诚实原则

没查到就说没查到。系统禁止用训练记忆冒充刚查的结果 —— 所以你会看到它明确说「未在历史会话中找到」，这是特性不是缺陷。

历史归档

每次会话结束会被归档成结构化条目，落在本地数据目录，可随时检索：

归档内容用途
会话摘要（意图 / 用到的工具 / 结果）回忆「那次是怎么做的」
主题与标签按项目、按技术栈聚合检索
教训条目（错误 → 修复）下次同类任务前主动避坑
用户偏好画像影响默认选择与表达方式
  • 本地存储：数据在你自己的机器上，不上传
  • 可查可改：说「看看你记住了我哪些偏好」，或「删掉那条过时的记忆」
  • 跨会话引用：可以用 @会话 的方式把某次历史会话拉进当前上下文

怎么用起来

推荐说法
  • 「记住：这个项目部署在 47.x 那台机器上」
  • 「上次那个 ESP32 烧录问题怎么解决的？」
  • 「查一下我们之前关于官网部署的会话」
  • 「这个坑记下来，以后别再犯」
效果
  • 新会话开场自带项目背景，不用重讲
  • 同类错误第二次出现时会被主动规避
  • 偏好被记住：默认输出格式、语气、交付方式
04

终端，以及通过终端启动 Cursor

看得见的终端：AI 敲的每一条命令你都能实时看到，也能随时接管。

可见终端（Visible Terminal）

Desktop Agent 的终端是真实 PTY，不是偷偷执行的后台进程 —— 界面里能看到命令逐行输出， 支持交互式程序（vim、top、REPL、Coding CLI 都能跑）。

你能做的
  • 实时围观 AI 执行的命令与输出
  • 随时插话纠正方向
  • 让 AI 读回终端日志、按关键字检索
  • 要求停掉 / 关闭某个终端
适合场景
  • 起本地服务（llama-server、http.server）
  • 跑构建 / 测试 / 部署命令
  • 长驻交互式进程
  • 委托 Coding CLI 做多轮开发
主机 Shell

终端跑的是你本机的真实 Shell（macOS 为 zsh，Windows 为对应 ShellKind）， 不是对话里随口给的示例命令。所以路径、环境变量都与你日常一致。

通过终端启动 Cursor（Coding CLI）

Desktop Agent 可以把开发任务委托给本机的 Coding CLI（Cursor / Claude / Codex 等）， 由它在真实终端里读仓、出方案、改代码，主脑负责澄清需求、确认目录、验收结果。

关键

走的是 Cursor 的命令行 agent，不是 IDE 图形界面。 在 Windows 上直接敲 cursor … 会弹出 IDE，这类调用会被拒绝。 正确入口是统一 runner：

# 统一入口（provider 可换 claude / codex） python "<DESKTOP_AGENT_ROOT>/skills/coding_cli/scripts/run_coding_cli.py" \ --provider cursor --workspace "<项目绝对路径>" \ --mode plan --prompt-file "<需求索引.md>"

标准流程

  1. 确认 CLI 可用agent --version 能返回版本即已安装；未登录时执行 agent login 或配置 API Key（安装与登录都会先征得你同意）。
  2. 确认项目绝对路径必须由你明确给出或勾选，不会拿当前目录瞎猜。
  3. 需求落盘把澄清后的需求写进项目的 chat/ 目录，终端里只传一份短索引，避免长文塞爆 CLI。
  4. 先方案后改码默认 plan / ask 模式，你看过方案并授权后才升级到 write。模式升级会自动开新的可写终端会话。
  5. 验收改完必须跑测试（仓库自带 pytest / npm test / go test），核对文件确实被改，才算完成。
模式能做什么何时用
plan只出实施方案，不改文件动手前先对齐思路
ask问答式勘察仓库搞清楚代码结构 / 定位问题
write真实改码方案确认并授权之后

最省事的用法是直接说人话：「用 Cursor 帮我改这个项目：/Users/xx/proj，先出方案」 —— 上面这些纪律由主脑自动执行，你只需要在关键节点确认和授权。

终端纪律（安全边界）

  • 先看再杀：要停终端前先列出在跑的会话，不会盲杀正在运行的任务
  • 串行执行：Shell 命令按序跑，不会两条命令互相踩
  • 写操作有边界：只在会话工作区内写文件；要动别的目录必须先申请路径授权
  • 删除进回收站：删文件走系统回收站，可恢复，不做永久删除
  • 日志可追溯：长输出落盘归档，结论必须基于真实日志而不是猜测
  • 危险操作先问：不可逆动作会用选项卡跟你确认
